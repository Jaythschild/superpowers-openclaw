### [安全][AI 编程][OpenAI] OpenAI 详解 Codex Windows 沙箱：安全边界成为编码 Agent 基建

**来源**：OpenAI Engineering  
**链接**：https://openai.com/index/building-codex-windows-sandbox/

- OpenAI 解释了 Codex for Windows 沙箱的设计背景：在没有沙箱时，用户只能频繁审批命令，或开放 Full Access。
- 文章描述了从 **unelevated sandbox** 到 **elevated sandbox** 的迭代，目标是在可用性和安全性之间取得平衡。
- Codex 默认可读取广泛文件，但写入限制在工作区，并对网络访问、文件系统访问等进行控制。
- 这类设计直接影响 AI 编程产品能否被企业和高风险工程环境接受。

**纳斯判断**：Agent 越能干，越需要强边界。未来 AI 编程工具的竞争不只看模型能力，还要看权限模型、审计、沙箱和恢复机制。

### [视觉模型][Meta] SAM 3.1 提升视频目标检测与追踪效率

**来源**：Meta AI Blog  
**链接**：https://ai.meta.com/blog/segment-anything-model-3/

- Meta 更新 **SAM 3.1**，作为 SAM 3 的 drop-in replacement。
- 新模型通过 **object multiplexing** 在单次 forward pass 中追踪最多 16 个对象。

**纳斯判断**：视觉基础模型正在从“能分割”走向“能实时理解动态世界”。这对视频编辑、机器人、安防、自动标注和空间智能都有实际意义。

## 纳斯观察

今天最重要的变化不是某一个模型分数，而是 **Agent 产品的操作系统化**。

OpenAI 把 Codex 接到手机端，Anthropic 把 Agent 模板接到金融和办公套件，Meta 把多模态推理、工具调用和多 Agent 编排放进 Muse Spark，DeepSeek 与 Qwen 也在强调 Agent 能力、安全护栏和可部署组件。它们共同指向一个趋势：AI 不再只是回答问题，而是在越来越多场景里承担“持续推进任务”的角色。

对杰斯来说，接下来最值得投入的是两件事：第一，继续沉淀自己的 **Skill / 知识库 / 工具链**，让 Agent 更懂你的工作方式；第二，重视 **权限、沙箱、验收、回滚**，因为真正能长期使用的 Agent，一定既能干活，也能被可靠地控制。
