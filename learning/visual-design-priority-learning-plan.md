# 纳斯视觉设计能力学习计划（主次版）

创建时间：2026-05-12 11:32 GMT+8
目标：系统学习美术、设计、排版、字体、颜色、构图等能力，并优先服务杰斯的实际需求：AI 日报、PPT、图片生成、文档排版、网页/海报视觉表达。

---

## 一、最新资料与方法判断

基于 2026-05-12 查询到的资料，当前主流设计学习不再只是“看起来好看”，而是更强调：

1. **视觉层级与信息清晰度**
   - NN/g 强调好设计要有网格、清晰视觉层级、有意图的颜色和一致性。
   - 这对日报、PPT、网页排版最重要。

2. **可读性与可访问性**
   - WCAG 2.2 仍是网页和数字内容的重要标准。
   - 正文文字通常至少要满足 4.5:1 对比度；大文字至少 3:1；UI/图形关键元素通常至少 3:1。
   - 颜色不能作为唯一的信息表达方式，要配合文字、图标、形状或标签。

3. **字体与排版系统化**
   - Apple HIG 和 Material Design 都强调字体不仅是装饰，而是传达层级、可读性和品牌气质的核心工具。
   - 少用字体，多用字号、字重、颜色、间距建立层级。

4. **设计系统思维**
   - Figma Learn 近年的设计系统课程强调：颜色、字体、图标、间距、组件、命名、文档化。
   - 对纳斯来说，后续应该沉淀自己的“视觉规范”，而不是每次重新想。

5. **学习方式：案例拆解 + 模仿重做 + 输出复盘**
   - 最有效的方式不是只看理论，而是：
     - 看优秀案例
     - 拆解为什么好
     - 模仿一版
     - 改成自己的场景
     - 输出后复盘

## 二、学习目标分级

### A 级目标：最高优先级，立刻影响输出质量

#### A1. 视觉层级

必须掌握：
- 主标题、副标题、正文、注释、标签的层级关系
- 通过字号、字重、颜色、位置、留白控制阅读顺序
- 一页/一屏只突出一个核心重点

应用场景：
- AI 日报摘要
- PPT 封面和章节页
- 长文转卡片式信息
- 图片生成提示词中的视觉焦点描述

训练方法：
- 每次输出前问：用户第一眼应该看哪里？第二眼看哪里？最后记住什么？

---

#### A2. 排版与留白

必须掌握：
- 网格意识
- 对齐关系
- 边距、段距、行距
- 卡片式布局
- 信息密度控制

应用场景：
- 飞书日报排版
- PPT 页面布局
- 海报/封面/社媒图
- 文档结构优化

训练方法：
- 少堆砌，多分组
- 用留白制造高级感
- 用模块化结构提高阅读效率

---

#### A3. 字体与可读性

必须掌握：
- 中文正文优先清晰，不乱用花字
- 标题可以更有风格，但正文必须舒服
- 字号、字重、行距、字距共同决定阅读体验
- 中英数字混排要协调

应用场景：
- AI 日报
- PPT 标题
- 网页标题/正文
- 设计图中文字提示

训练方法：
- 控制字体数量：通常 1-2 套即可
- 用字重和字号建立层级，而不是频繁换字体

---

#### A4. 色彩与对比

必须掌握：
- 主色、辅助色、强调色
- 冷暖、明暗、饱和度
- 文字和背景对比度
- 不靠颜色单独传达含义

应用场景：
- 日报标签
- PPT 视觉主题
- 图表高亮
- 图片生成风格控制

训练方法：
- 默认先保证可读性，再追求炫
- 用少量强调色，而不是满屏彩色

---

### B 级目标：中期提升审美和专业度

#### B1. 构图

学习内容：
- 三分法
- 中心构图
- 对角线构图
- 框景构图
- 前中后景
- 视觉动线

应用场景：
- 图片生成
- 海报设计
- PPT 封面
- 文章头图

训练方法：
- 看到图片时拆解：主体在哪？动线是什么？背景如何服务主体？

---

#### B2. 美术基础

学习内容：
- 点线面
- 形体比例
- 明暗关系
- 空间透视
- 材质与光影

应用场景：
- 生成图提示词更准确
- 判断画面是否高级
- 做视觉描述时更专业

训练方法：
- 每次生成图片时明确：光线、镜头、材质、风格、构图、色彩

---

#### B3. 设计系统

学习内容：
- 色彩 token
- 字体样式
- 间距规范
- 组件一致性
- 命名与文档化

应用场景：
- 统一 AI 日报风格
- 统一 PPT 风格
- 统一纳斯输出审美

训练方法：
- 逐渐沉淀“纳斯视觉规范”：
  - 日报模板
  - PPT 模板
  - 图片提示词模板
  - 色彩组合库
  - 字体搭配库

---

### C 级目标：长期艺术修养

#### C1. 设计史与风格

学习内容：
- 包豪斯
- 瑞士国际主义风格
- 日式留白
- 现代主义
- 杂志编辑设计
- 科技极简风

用途：
- 增强审美判断
- 让输出更有“风格来源”

---

#### C2. 品牌与情绪表达

学习内容：
- 不同颜色/字体/构图对应的情绪
- 品牌一致性
- 视觉人格

用途：
- 让纳斯输出更符合“温暖、正能量、有品质感”的人格

## 三、阶段计划

目标：明显提升日报、PPT、文档的清晰度。

每天训练重点：
1. 视觉层级

## 四、每次输出前的自检清单

### 信息清晰度
- 这一页/这张图/这段内容的核心是什么？
- 用户第一眼能看到重点吗？
- 有没有信息过载？

### 排版
- 是否对齐？
- 边距是否舒服？
- 行距和段距是否利于阅读？
- 留白是否足够？

### 字体
- 字体是否过多？
- 标题、正文、注释是否有层级？
- 中文和英文/数字是否协调？

### 色彩
- 主色是否明确？
- 强调色是否克制？
- 文字和背景对比是否足够？
- 有没有只靠颜色传达含义？

### 构图
- 主体是否明确？
- 视觉动线是否自然？
- 背景是否服务主体？

## 五、优先学习顺序

1. 视觉层级
2. 排版与留白
3. 字体可读性
4. 色彩与对比
5. 构图
6. 美术基础
7. 设计系统
8. 设计史与风格
9. 品牌情绪表达

理由：
- 前四项最直接影响杰斯每天看到的输出质量。
- 构图和美术基础提升图片/PPT审美。
- 设计系统用于长期稳定输出。
- 设计史和品牌表达属于长期审美修养。

## 可查证参考页面（2026-05-12 补充）

### Apple Human Interface Guidelines

- Human Interface Guidelines 总入口  
  https://developer.apple.com/design/human-interface-guidelines
  - 参考点：Hierarchy、Harmony、Consistency，以及 Design fundamentals 中的 Color、Layout、Typography、Accessibility。

- Typography  
  https://developer.apple.com/design/human-interface-guidelines/typography
  - 参考点：字体用于可读性、信息层级、内容强调和品牌风格；减少字体数量；避免小字号使用过细字重。

- Accessibility  
  https://developer.apple.com/design/human-interface-guidelines/accessibility
  - 参考点：文字可读性、动态字体、颜色对比、不要只靠颜色表达信息、控件尺寸和间距。

### Material Design / Material 3

- Material 3 Color system overview  
  https://m3.material.io/styles/color/system/overview
  - 参考点：颜色系统、色彩角色、可访问性、主题色与界面角色。

- Material 3 Color roles  
  https://m3.material.io/styles/color/roles
  - 参考点：primary、secondary、tertiary、surface、error、on-color 等角色分工。

- Material 3 Typography overview  
  https://m3.material.io/styles/typography/overview
  - 参考点：字体系统用于阅读、美感和内容层级。

- Material 3 Type scale tokens  
  https://m3.material.io/styles/typography/type-scale-tokens
  - 参考点：display、headline、title、body、label 等字体角色。

- Material 3 Layout overview  
  https://m3.material.io/foundations/layout/overview

- Android Developers: Material Design 3 in Compose

  https://www.w3.org/TR/WCAG22/

- WCAG 2.2 Contrast Minimum / 1.4.3  
  https://www.w3.org/TR/WCAG22/#contrast-minimum

  https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html
