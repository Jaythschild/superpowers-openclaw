# 视觉设计图文课程｜OpenDesign AI 科技风系统版 v4

面向 AI 日报、飞书知识库、PPT、教程和图文报告。  
这一版不再把内容一段段补进去，而是用 OpenDesign 的工作流重新设计整套课程：先定内容目标，再定视觉方向，再做案例图，最后做生成后检查。

## 封面｜从内容整理到视觉作品

这门课训练的不是“把页面装饰得更科技”，而是把信息变成一套可阅读、可教学、可复用的视觉系统。

本版统一采用三层设计方向：

- Data Drift：负责 AI、数据流、智能系统和未来感。
- Swiss Pulse：负责网格、秩序、信息密度和报告结构。
- Velvet Standard：负责克制留白、高级质感和少色彩控制。

本版交付标准：

- 每个知识点都有对应案例。
- 每个案例都有配图和文字说明。
- 图片必须解释概念，不能只做氛围。
- 课程、教程、日报、图文报告使用同一套内容设计流程。
- 写入飞书后必须检查结构、图片、重复内容和旧版残留。

## OpenDesign 工作流｜先设计课程，再生成内容

OpenDesign 在这里不是一个名字，而是一套工作方式：

1. 需求锁定：明确读者、用途、输出格式和成功标准。
2. 方向选择：先选视觉方向，避免每一节都随机发挥。
3. 设计系统：把颜色、字体、网格、卡片、图像风格固定下来。
4. 内容设计：每个知识点都配概念、案例、操作步骤和检查清单。
5. 生成验收：文档生成后检查是否统一、好看、可读、可用。

不要先写一堆内容再临时补图。正确顺序是：先设计阅读路径，再写正文，再做配图。

## 第一课｜视觉层级：先给观看顺序

### 学习目标

让读者第一眼知道先看哪里、第二眼看什么、最后该拿走什么结论。

### 核心概念

视觉层级不是把标题放大这么简单，而是安排注意力：

- 第一视线：主结论。
- 第二视线：关键证据。
- 第三视线：来源、限制和补充说明。

### 案例

把 AI 日报首页从“新闻列表”改成“今日主线 + 三条证据”。

改前：  
页面上全是新闻标题，读者需要自己归纳今天的重点。

改后：  
先给一句主判断，例如“今日 AI 主线是 Agent 工具进入办公场景”，再放三条证据新闻，最后放来源和限制。

### 操作步骤

1. 找出整页最重要的一句话。
2. 把这句话放到第一屏最强位置。
3. 把证据压缩成 2-3 条。
4. 来源和补充信息降权处理。

### 检查

遮住正文，只看标题和图，是否还能知道这页讲什么？如果不能，视觉层级还没成立。

## 第二课｜中文排版：长文要有呼吸

### 学习目标

把中文长文整理成能快速扫读的教程页面，而不是一整块灰色文本。

### 核心概念

中文排版要解决四件事：

- 标题写判断，不写空泛主题。
- 摘要负责快速理解。
- 正文短句化。
- 注释和来源降权，但保持可信。

### 案例

把一段 500 字学习记录压成：1 个判断、3 条证据、1 个练习。

改前：  
“今天学习了很多关于排版和配色的内容……”这种写法像流水账。

改后：  
“图文报告的关键不是更好看，而是让读者少归纳一步。”  
证据 1：标题从栏目名改成判断句。  
证据 2：正文从材料列表改成三段推理。  
证据 3：图片从装饰改成解释结构。  
练习：把一篇日报改写成主判断 + 三条证据。

### 操作步骤

1. 删除重复解释。
2. 每段只保留一个信息点。
3. 长句拆成短句。
4. 用小标题承接阅读节奏。

### 检查

手机端阅读时，是否需要连续滑很多屏才看到重点？如果是，说明段落还太重。

## 第三课｜色彩系统：颜色承担角色

### 学习目标

让颜色帮助理解，而不是制造热闹。

### 核心概念

颜色必须有角色：

- 白色或高亮文字：主结论。
- 蓝色：证据、路径、数据关系。
- 绿色：行动、完成、可执行步骤。
- 琥珀色：风险、异常、注意事项。
- 深色背景：承载空间和高级感。

### 案例

日报里所有“机会”使用蓝色路径，所有“风险”只用少量琥珀提醒。

改前：  
每个栏目都换颜色，看起来热闹，但读者不知道颜色代表什么。

改后：  
同一类信息永远用同一类颜色。读者看到琥珀色就知道是风险，看到绿色就知道是行动。

### 操作步骤

1. 先写颜色角色表。
2. 一页只选一个主强调色。
3. 不让背景、标题、图表、按钮同时抢注意力。
4. 状态色只在关键处使用。

### 检查

把所有文字遮住，只看颜色，是否还能分辨结论、证据、风险和行动？如果不能，色彩系统还没成立。

## 第四课｜报告版式：材料变成路径

### 学习目标

把资料堆叠变成阅读路径，让读者顺着逻辑走。

### 核心概念

报告应该像一次讲解，而不是一个文件夹：

- 先给主线。
- 再给证据。
- 再解释影响。
- 最后给行动建议。

### 案例

把工具调研从功能清单改成“适用场景 -> 风险 -> 是否接入”。

改前：  
列出工具 A、工具 B、工具 C 的功能，读者看完不知道该选哪个。

改后：  
先说结论：“工具 A 适合试用，但暂不接入生产。”  
再说证据：“它的自动化链路完整，但权限边界不清晰。”  
最后给动作：“进入观察清单，等待两周社区反馈。”

### 操作步骤

1. 写一句主判断。
2. 删除不支撑判断的材料。
3. 把证据按推理顺序排列。
4. 用“下一步”收束。

### 检查

读完报告后，读者是否知道下一步该做什么？如果不知道，版式只是整理，不是表达。

## 第五课｜信息图标注：让图自己说话

### 学习目标

让图片和图表自己承担解释功能，减少读者在正文和图之间来回找答案。

### 核心概念

信息图至少包含四件事：

- 结论标题。
- 关键证据。
- 直接标注。
- 来源或口径说明。

### 案例

把“新闻分类占比”改成“Agent 内容占比最高，值得继续跟踪”。

改前：  
图表标题只写指标名，读者要自己判断哪个分类重要。

改后：  
标题直接写结论，最大占比旁边加标注，底部补来源和统计口径。

### 操作步骤

1. 把图表标题改成判断句。
2. 直接标注关键数值。
3. 减少复杂图例。
4. 把口径和来源放到底部低权重区域。

### 检查

只看图，不看正文，能不能说出主要结论？不能的话，这张图还只是素材。

## 第六课｜案例配图：每个案例一图一文

### 学习目标

让每个知识点都有可见示例，而不是只有原则。

### 核心概念

配图不是装饰。它必须承担一种教学功能：

- 对比：改前 vs 改后。
- 流程：第一步 -> 第二步 -> 第三步。
- 结构：主结论、证据、行动的位置。
- 检查：交付前要看哪些点。

### 案例

每节教程至少一张图：对比、流程、结构或检查清单。

改前：  
文字写得很多，但没有图，读者只能凭想象理解。

改后：  
每个案例旁边有一张对应图卡，图里标出结论、证据、动作和检查点。

### 操作步骤

1. 先判断这个知识点适合哪类图。
2. 写图的主结论。
3. 控制图中元素数量。
4. 给图配一段解释文字。

### 检查

这张图是否能替正文解释 50% 的内容？如果不能，它就不是教程图。

## 第七课｜交付检查：生成后必须验收

### 学习目标

把审美和质量变成可检查的动作。

### 核心概念

文档生成后不能直接交付。必须检查四层：

- 结构：是否是一套系统课程？
- 审美：风格是否统一？
- 教学：是否每个知识点有案例？
- 技术：飞书图片 token 是否非空，是否没有空块和重复段落？

### 案例

写入飞书后确认：新章节存在、图片非空、没有空块和重复段落。

改前：  
只说“已同步”，但没有验证图片、结构和残留内容。

改后：  
读取飞书文档，检查关键词、block 数量、图片数量、空图片块、旧标题残留和新增内容位置。

### 操作步骤

1. 写入前备份旧文档。
2. 写入后读取全文。
3. 列出 blocks。
4. 检查图片 token。
5. 检查旧版标题和重复内容。
6. 把结果告诉杰斯。

### 检查

如果没有检查结果，就不能说完成。

## 统一应用规则

### 应用到教程

教程必须包含：学习目标、核心概念、案例、操作步骤、检查。每个案例配一张对应图。

### 应用到日报

日报必须包含：今日主线、影响图卡、分栏目证据、纳斯观察、来源和限制。不能只堆新闻。

### 应用到图文报告

图文报告必须包含：主判断、关键证据、行动建议和解释性配图。

### 应用到飞书 Wiki

新增内容必须进入已有课程体系。报告、学习记录、调研材料只能作为素材，不能原文塞进文档。
